* Quick start: one-command pipeline launcher
:PROPERTIES:
:CUSTOM_ID: quick-start-one-command-pipeline-launcher
:END:
The launcher starts and supervises =BunrakuOSCEncoder= and
=BunrakuOSCDecoder=. With no arguments it starts the local-only pipeline
and does not start =OscGroupClient=:

#+begin_src sh
./PipelineApplications/start_bumochi_pipeline.sh
#+end_src

Run that command from the root of the BuMoChi repository. It uses the
standard local ports automatically:

#+begin_src text
XR-Animator -> encoder 39537 -> Bmc 57130 -> decoder 39538 -> Godot 39539
#+end_src

The launcher does not start XR-Animator, SuperCollider, or Godot. Start
those three applications separately. Recompile the SuperCollider class
library so that Bmc listens on =57130=, configure XR-Animator to send to
=39537=, and run a Godot avatar receiver on =39539=.

** Meaning of the launcher =--avatar= option
:PROPERTIES:
:CUSTOM_ID: meaning-of-the-launcher---avatar-option
:END:
The =--avatar= option identifies which animation figure is controlled by
the local motion-capture stream received by =BunrakuOSCEncoder=. It does
not change XR-Animator's UDP destination. XR-Animator still sends VMC to
the encoder's listen port, =127.0.0.1:39537= by default. The encoder
adds the selected avatar name to every frame received on that port, and
Bmc uses that name to select the matching registered =BmcAvatar=.

For example:

#+begin_src sh
./start_bumochi_pipeline.sh --avatar Mother
#+end_src

means:

#+begin_src text
XR-Animator camera motion
    -> UDP 39537
    -> BunrakuOSCEncoder labels each frame "Mother"
    -> Bmc.avatar(\Mother)
    -> Mother's configured vmcPort
#+end_src

It does *not* mean that Mother uses UDP port =39537= in Godot. Port
=39537= is only the local XR-Animator-to-encoder connection. Mother's
Godot destination is set separately in SuperCollider, for example:

#+begin_src supercollider
Bmc.addAvatar(\Mother, "Mother").vmcPort_(39540);
#+end_src

The encoder avatar name and the Bmc registration key must match exactly.
The launcher's default is =--avatar Ishidomaru=; use =--avatar Mother=
when the local XR-Animator camera should control Mother. Changing this
option requires restarting the encoder because it is a process startup
setting.

To include OSCGroups, supply an OSC server address and a unique
username:

#+begin_src sh
./PipelineApplications/start_bumochi_pipeline.sh \
  --oscserver SERVER_ADDRESS \
  --username PerformerA
#+end_src

OSCGroups mode uses these additional defaults:

| Setting                   | Default   | Override              |
|---------------------------+-----------+-----------------------|
| Group name                | =bumochi= | =--groupname NAME=    |
| User and group password   | =bmc123=  | =--password PASSWORD= |
| Server port               | =22242=   | =--server-port PORT=  |
| Local network-facing port | =22243=   | =--local-port PORT=   |

The password =bmc123= is a convenient rehearsal default, not a secure
public-network credential. Set a different password for an exposed
OSCGroups server.

Inspect every available launcher option without starting anything:

#+begin_src sh
./PipelineApplications/start_bumochi_pipeline.sh --help
#+end_src

Stop all helper processes started by the launcher with =Control-C= in
its terminal.

When the launcher is started with =--verbose=, follow the live encoder
and decoder output in another terminal:

#+begin_src sh
tail -f "$TMPDIR/bumochi-pipeline-$USER/encoder.log" \
        "$TMPDIR/bumochi-pipeline-$USER/decoder.log"
#+end_src

The launcher starts Python in unbuffered mode, so new log lines appear
immediately.

* Cheatsheet! Check the active Bmc port configuration
:PROPERTIES:
:CUSTOM_ID: cheatsheet-check-the-active-bmc-port-configuration
:END:
Your VMC mocap applications (XR-Animator, Waidayo, or other) and Godot
should be configured to send/receive animation data at the ports
required by the pipeline. To check these port numbers, after recompiling
the SuperCollider class library, evaluate:

#+begin_src supercollider
Bmc.help;
#+end_src

The default summary is equivalent to:

#+begin_src text
XR-Animator output port: 39537
BunrakuOSCEncoder output port: 57130
SuperCollider VMC/OSC input port: 57130
SuperCollider VMC/OSC output port: 39538
BunrakuOSCDecoder input port: 39538
BunrakuOSCDecoder output ports:
  Ishidomaru: 39539
#+end_src

The final list is generated from the avatars currently configured in
Bmc, so it expands when additional avatar routes are added. Run
=Bmc.help;= again after changing any ports.

The following sections are only necessary if you want to customize the
pipeline or check for errors.

* Details
:PROPERTIES:
:CUSTOM_ID: details
:END:
This guide provides information to troubleshoot or tweak the internal
port numbers of all applications of the pipeline. It shows how to start
and configure the six applications in the following downstream order:

| No. | Application         | Input/listening port | Output/destination port     | Required configuration                                                                                                                                                                                                 |
|-----+---------------------+----------------------+-----------------------------+------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1   | XR-Animator         | ---                  | =39537=                     | Send standard VMC to =BunrakuOSCEncoder= on =127.0.0.1:39537=.                                                                                                                                                         |
| 2   | =BunrakuOSCEncoder= | =39537=              | =57130=; optionally =22244= | Listen for XR-Animator; always send route-free frames to local Bmc on =57130=; in OSCGroups mode, send an identical copy to local =OscGroupClient= on =22244=.                                                         |
| 3   | =OscGroupClient=    | =22244=              | =57130=                     | Receive local encoder frames on =22244=; deliver remote collaborators' frames to local Bmc on =57130=. The client also connects to =OscGroupServer= port =22242= through a client-specific local port such as =22243=. |
| 4   | SuperCollider / Bmc | =57130=              | =39538=                     | Receive local and remote route-free frames; synthesize the local scene; send routed frames to =BunrakuOSCDecoder= on =39538=. Ishidomaru's default routed frames embed Godot destination =39539=.                      |
| 5   | =BunrakuOSCDecoder= | =39538=              | =39539=                     | Receive routed Bmc frames, reconstruct standard VMC, and forward Ishidomaru to the embedded Godot port =39539=.                                                                                                        |
| 6   | Godot               | =39539=              | ---                         | Run an Ishidomaru VMC receiver listening on =39539= and render the animation locally.                                                                                                                                  |

The resulting application and port sequence is:

#+begin_src text
1. XR-Animator          --VMC 39537----------> 2. BunrakuOSCEncoder
2. BunrakuOSCEncoder   --frames 57130--------> 4. SuperCollider / Bmc
2. BunrakuOSCEncoder   --frames 22244--------> 3. OscGroupClient
3. OscGroupClient      --remote frames 57130-> 4. SuperCollider / Bmc
4. SuperCollider / Bmc --routed frames 39538-> 5. BunrakuOSCDecoder
5. BunrakuOSCDecoder   --VMC 39539-----------> 6. Godot / Ishidomaru
#+end_src

The procedure uses the default single-avatar Ishidomaru configuration.
Ishidomaru's Godot VMC receiver listens on =39539=.

Run all terminal commands from the root of the BuMoChi repository unless
the command uses a globally installed launcher.

Only the receiving application owns a UDP listening port. Several
applications may send packets to Bmc on =57130= without conflict because
Bmc is the single listener.

* Before starting
:PROPERTIES:
:CUSTOM_ID: before-starting
:END:
1. Confirm that Python 3 is available:

#+begin_src sh
python3 --version
#+end_src

2. [@2] For OSCGroups collaboration only, obtain the =OscGroupServer=
   address and a unique username from the session organiser. Confirm
   whether the session uses the default group =bumochi= and password
   =bmc123= or overrides them.

3. For OSCGroups collaboration only, give this workstation a unique
   OSCGroups username and encoder =--source= identity. The launcher uses
   local network-facing port =22243= unless it is overridden.

4. Stop older encoder, decoder, and =OscGroupClient= processes. If
   needed, inspect the local receiving ports:

#+begin_src sh
lsof -nP -iUDP:39537
lsof -nP -iUDP:22244
lsof -nP -iUDP:57130
lsof -nP -iUDP:39538
lsof -nP -iUDP:39539
#+end_src

* 1. XR-Animator
:PROPERTIES:
:CUSTOM_ID: 1-xr-animator
:END:
1. Start XR-Animator.
2. Open its VMC/OSC output settings.
3. Set the VMC destination to:

#+begin_src text
Host: 127.0.0.1
Port: 39537
#+end_src

4. [@4] Enable full-body VMC output.

XR-Animator may start before the encoder. UDP frames sent before the
encoder begins listening are simply discarded.

For screenshots and detailed configuration instructions, see
[[file:PortNumberSetup.md#1-xr-animator-vmc-output-port][XR-Animator VMC output port]]
and
[[file:HelperApplications/BunrakuOSCEncoder.md#configure-xr-animator][Configure XR-Animator]].

* 2. BunrakuOSCEncoder
:PROPERTIES:
:CUSTOM_ID: 2-bunrakuoscencoder
:END:
Open a Terminal window at the BuMoChi repository root and start the
encoder with every relevant port written explicitly:

#+begin_src sh
python3 PipelineApplications/BunrakuOSCEncoder.py \
  --listen-ip 127.0.0.1 \
  --listen-port 39537 \
  --bmc-ip 127.0.0.1 \
  --bmc-port 57130 \
  --oscgroups-ip 127.0.0.1 \
  --oscgroups-port 22244 \
  --avatar "Ishidomaru" \
  --source "workstation-a-xr-animator" \
  --verbose
#+end_src

Replace =workstation-a-xr-animator= with a stable source identity unique
to this workstation. Leave this terminal open.

Here =--avatar "Ishidomaru"= means that the local XR-Animator stream
arriving on =39537= is labelled as Ishidomaru motion. Replace it with
=--avatar "Mother"= if the camera should control the Bmc avatar
registered as =\Mother=. This identity setting is independent of both
the encoder listen port and the avatar's final Godot =vmcPort=.

The encoder produces two identical route-free source-frame copies:

#+begin_src text
local copy   -> UDP 57130 -> local Bmc
network copy -> UDP 22244 -> local OscGroupClient
#+end_src

Because this startup order places the encoder before =OscGroupClient=
and Bmc, its first outgoing packets may be discarded. Normal delivery
begins as soon as those receivers start.

If the globally installed launcher is available, the equivalent command
is:

#+begin_src sh
BunrakuOSCEncoder \
  --listen-ip 127.0.0.1 \
  --listen-port 39537 \
  --bmc-ip 127.0.0.1 \
  --bmc-port 57130 \
  --oscgroups-ip 127.0.0.1 \
  --oscgroups-port 22244 \
  --avatar "Ishidomaru" \
  --source "workstation-a-xr-animator" \
  --verbose
#+end_src

For installation, options, and diagnostic instructions, see
[[file:HelperApplications/BunrakuOSCEncoder.md#how-to-start-bunrakuoscencoder][How to start BunrakuOSCEncoder]]
and
[[file:HelperApplications/BunrakuOSCEncoder.md#test-and-diagnose][Test and diagnose BunrakuOSCEncoder]].

* 3. OscGroupClient
:PROPERTIES:
:CUSTOM_ID: 3-oscgroupclient
:END:
Open a second Terminal window at the BuMoChi repository root.

=OscGroupClient= requires nine positional arguments in this order:

#+begin_src text
OscGroupClient SERVER_ADDRESS SERVER_PORT LOCAL_TO_REMOTE_PORT INPUT_PORT OUTPUT_PORT USER_NAME USER_PASSWORD GROUP_NAME GROUP_PASSWORD
#+end_src

Start the bundled macOS client with:

#+begin_src sh
HelperAppsAndExamples/OSCGroups/bin/macos/OscGroupClient \
  SERVER_ADDRESS 22242 22243 22244 57130 \
  USER_NAME USER_PASSWORD GROUP_NAME GROUP_PASSWORD
#+end_src

Replace all uppercase placeholders. Replace example local port =22243=
if it is occupied or if another client on this computer uses it. Leave
this terminal open.

The important application-facing ports are:

#+begin_src text
OscGroupClient input:  UDP 22244 <- local encoder frames for sharing
OscGroupClient output: UDP 57130 -> remote source frames delivered to local Bmc
#+end_src

Do not set the client output to decoder port =39538=. Remote route-free
frames must enter Bmc first for local selection, composition, recording,
and synthesis.

If the globally installed client is available, use the same arguments:

#+begin_src sh
OscGroupClient \
  SERVER_ADDRESS 22242 22243 22244 57130 \
  USER_NAME USER_PASSWORD GROUP_NAME GROUP_PASSWORD
#+end_src

For argument definitions, installation, and checks, see
[[file:HelperApplications/OSCGroupsClient.md#how-to-start-oscgroupclient][How to start OscGroupClient]],
[[file:HelperApplications/OSCGroupsClient.md#command-line-arguments][OscGroupClient command-line arguments]],
and
[[file:PortNumberSetup.md#2-oscgroupclient-port][OSCGroupClient port]].

* 4. SuperCollider
:PROPERTIES:
:CUSTOM_ID: 4-supercollider
:END:
1. Start SuperCollider.
2. Recompile the class library if necessary with *Language → Recompile
   Class Library*.
3. After compilation, Bmc automatically listens for =/bunraku/vmc/frame=
   on UDP =57130=.
4. Evaluate this block to verify and explicitly restore the default
   Ishidomaru route:

#+begin_src supercollider
(
Bmc.avatar(\Ishidomaru).vmcPort_(39539);
Bmc.decoderPort_(39538);
Bmc.forwardDecoder_(true);
Bmc.start(57130);
Bmc.status;
)
#+end_src

5. [@5] Open the live input monitor:

#+begin_src supercollider
Bmc.showDispatcherStatus;
#+end_src

Its static field should say:

#+begin_src text
Listening for '/bunraku/vmc/frame' on port: 57130
#+end_src

The dynamic =received= count should increase while XR-Animator is
sending. It may include both local frames received directly from the
encoder and remote frames received through =OscGroupClient=.

For details, see
[[file:PortNumberSetup.md#3-supercollider-port-listening-to-oscgroupclient][SuperCollider port listening to OSCGroupClient]],
[[file:PortNumberSetup.md#default-forwarding-pipeline-of-bumochi-after-fresh-library-compile][Default forwarding pipeline of BuMoChi]],
and [[../UserGuide.md#system-control][Bmc system control]].

* 5. BunrakuOSCDecoder
:PROPERTIES:
:CUSTOM_ID: 5-bunrakuoscdecoder
:END:
Open a third Terminal window at the BuMoChi repository root and start
the decoder:

#+begin_src sh
python3 PipelineApplications/BunrakuOSCDecoder.py \
  --listen-ip 127.0.0.1 \
  --listen-port 39538 \
  --target-ip 127.0.0.1 \
  --verbose
#+end_src

Leave this terminal open. The decoder receives locally synthesized
routed frames from Bmc on =39538=, reads the embedded avatar
destination, reconstructs standard VMC bundles, and sends Ishidomaru's
bundles to Godot on =39539=.

If the globally installed launcher is available, the equivalent command
is:

#+begin_src sh
BunrakuOSCDecoder \
  --listen-ip 127.0.0.1 \
  --listen-port 39538 \
  --target-ip 127.0.0.1 \
  --verbose
#+end_src

The same decoder accepts every valid destination embedded by Bmc, so a
multi-avatar scene requires no different decoder command:

#+begin_src sh
python3 PipelineApplications/BunrakuOSCDecoder.py \
  --listen-ip 127.0.0.1 \
  --listen-port 39538 \
  --target-ip 127.0.0.1 \
  --verbose
#+end_src

For installation, options, and diagnostics, see
[[file:HelperApplications/BunrakuOSCDecoder.md#how-to-start-bunrakuoscdecoder][How to start BunrakuOSCDecoder]]
and
[[file:HelperApplications/BunrakuOSCDecoder.md#test-and-diagnose][Test and diagnose BunrakuOSCDecoder]].

* 6. Godot
:PROPERTIES:
:CUSTOM_ID: 6-godot
:END:
1. Start Godot and open the intended avatar project.
2. For the default single-avatar test, open =Seed_2_Ishidomaru_C=.
3. Confirm that the project's Ishidomaru VMC receiver listens on UDP
   =39539=.
4. Run the project scene.

Godot may start last. VMC bundles sent before its receiver starts are
discarded; live animation begins when the scene is running and
listening.

For detailed inspection and configuration instructions, see
[[file:PortNumberSetup.md#4-godot-avatar-specific-listening-port][Godot avatar-specific listening port]].

For the uniform two-avatar E project, use two explicit receiver nodes:

| Avatar     | Receiver node          | UDP port | Body tracker name              | Face tracker name              |
|------------+------------------------+----------+--------------------------------+--------------------------------|
| Ishidomaru | =IshidomaruVMCTracker= | =39539=  | =/vmc/ishidomaru_body_tracker= | =/vmc/ishidomaru_face_tracker= |
| Mother     | =MotherVMCTracker=     | =39540=  | =/vmc/mother_body_tracker=     | =/vmc/mother_face_tracker=     |

When using that scene, set Bmc's avatar destinations accordingly. The
unrestricted routed-frame decoder does not need an avatar-specific
allow-list:

#+begin_src supercollider
Bmc.avatar(\Ishidomaru).vmcPort_(39539);
Bmc.addAvatar(\Mother, "Mother").vmcPort_(39540);
#+end_src

See
[[file:Multi-Avatar%20project%20port%20number%20setting%20in%20godot%20-%20NOTES.md#set-the-vmc-port-numbers-for-mother-and-ishidomaru][Multi-Avatar project port number setting in Godot]]
for the explicit-receiver arrangement.

* Verify the complete pipeline
:PROPERTIES:
:CUSTOM_ID: verify-the-complete-pipeline
:END:
1. XR-Animator reports that VMC output is enabled for =127.0.0.1:39537=.
2. The encoder's =received=, =bmc_sent=, and =oscgroups_sent= counters
   increase.
3. =OscGroupClient= reports successful server and group registration.
4. =Bmc.showDispatcherStatus= reports =running: true=, port =57130=, and
   an increasing =received= count.
5. The decoder reports incoming frames on =39538= and VMC output to
   =39539=.
6. Ishidomaru moves in Godot.

To test only the final SuperCollider-to-Godot path, evaluate:

#+begin_src supercollider
Bmc.sendCalibrationFrame;
#+end_src

* Shutdown
:PROPERTIES:
:CUSTOM_ID: shutdown
:END:
Stop the applications in reverse order:

1. Stop the running Godot scene.
2. Stop =BunrakuOSCDecoder= with =Control-C=.
3. Evaluate =Bmc.stop;= in SuperCollider.
4. Stop =OscGroupClient= with =Control-C=.
5. Stop =BunrakuOSCEncoder= with =Control-C=.
6. Disable XR-Animator VMC output or quit XR-Animator.
