#+title: OSCGroups Use and Configuration

OSCGroups distributes route-free motion-source frames between workstations. It does not distribute completed figures, routed avatar frames, decoder output, or Godot VMC output.

* Local data flow

#+begin_example
local encoder -> 127.0.0.1:57130 -> local Bmc
local encoder -> 127.0.0.1:22244 -> OscGroupClient -> network
network -> OscGroupClient -> 127.0.0.1:57130 -> local Bmc
local Bmc -> 127.0.0.1:39538 -> decoder -> local Godot
#+end_example

This realizes distributed sources with local synthesis: each Bmc receives local and remote sources, constructs the complete animation scene locally, and sends only to its local renderer pipeline.

* Encoder distribution controls

The encoder supplies both source-frame copies by default:

#+begin_src sh
BunrakuOSCEncoder \
  --bmc-ip 127.0.0.1 --bmc-port 57130 \
  --oscgroups-ip 127.0.0.1 --oscgroups-port 22244 \
  --avatar "PerformerA" \
  --source "workstation-a-xr-animator"
#+end_src

Use =--no-oscgroups= for local-only operation or =--no-bmc= for a deliberate network-only diagnostic. At least one output must remain enabled.

* One client per workstation

The argument order is:

#+begin_example
OscGroupClient SERVER SERVER_PORT LOCAL_TO_REMOTE_PORT LOCAL_TX_PORT LOCAL_RX_PORT USER USER_PASSWORD GROUP GROUP_PASSWORD
#+end_example

Canonical BuMoChi launch:

#+begin_src sh
AppsAndCode/OSCGroups/bin/macos/OscGroupClient \
  SERVER_ADDRESS 22242 LOCAL_TO_REMOTE_PORT 22244 57130 \
  USER_NAME USER_PASSWORD GROUP_NAME GROUP_PASSWORD
#+end_src

- =localTxPort= =22244=: receives route-free frames from the local encoder for network transmission.
- =localRxPort= =57130=: delivers remote route-free frames to local Bmc.
- =localToRemotePort=: the client's network-facing local port; choose a free value as required by the setup.

One full-duplex client is enough for normal collaboration. Use unique usernames on different workstations.

* Server echo behavior

The server normally does not return a client's own frames to that client. Local monitoring still works because the encoder sends a separate identical copy directly to local Bmc.

* Prevent loops and bypasses

- Do not set =localRxPort= to =22244=: received frames would re-enter the transmit input.
- Do not set =localRxPort= to =39538=: remote source frames would bypass Bmc synthesis and incorrectly enter the decoder.
- Do not send Bmc output to =22244=.
- Do not send decoder or Godot VMC output to =22244=.
- Do not run an additional relay from Bmc or the decoder into OSCGroups.

* Diagnose

#+begin_src sh
lsof -nP -iUDP:57130
lsof -nP -iUDP:22244
lsof -nP -iUDP:39538
#+end_src

Bmc should own =57130=, =OscGroupClient= should own =22244=, and the decoder should own =39538=. The local encoder and local client both send to Bmc on =57130=.
